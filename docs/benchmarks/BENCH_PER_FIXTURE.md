# Per-fixture best-config benchmark

This document records, for every benchmark fixture, the **retrieval configuration that
maximizes that fixture's held-out quality** — measured, not asserted. It is the audit
trail for the README "best achievable" table and for the `<best_configuration>` blocks
in `prompts/frameworks/*.md`. Every number here is produced by the unmodified ranking
engine via `bench/cell.mjs` / `bench/repeat-score.mjs` and stored under `bench/results/`.

> **Host:** Apple M2 Mac mini (24 GB), macOS. Any throughput / build-cost figure (chunks/s)
> is **hardware-dependent** — expect different figures on other chips. Accuracy metrics are
> hardware-independent.

## What changed in v2 — higher statistical power

The previous run used a **held-out split of n=3** (symfony n=4). With a binary success
metric, n=3 admits only the values {0.00, 0.33, 0.67, 1.00}: a single query moves
held-out success@5 by 0.33, and the 95% confidence interval on any proportion spans
roughly ±0.5. Twelve fixtures "saturated" at 1.00 purely because three easy queries all
hit. Those conclusions were directional, not defensible.

This pass **expands every measurable suite's held-out split to n=17–20** (and tuning to
22–24), authored to the same difficulty distribution and verified against the real chunk
universe (see "Ground-truth gate" under Corrections). The entire config grid was then
re-measured against the expanded suites. The mean 95% Wilson CI half-width on held
success@5 fell from **±0.34 (n=3) to ±0.16 (n≈19) — 52% tighter** — enough to detect a
real 0.20 difference at ~80% power. Several headline n=3 conclusions did not survive.

## What "best config" means here

The winner for a fixture is selected on the **held-out** split (the ~45% of queries
authored fresh and never used to tune ranking), in this order:

1. **held-out success@5 (strict)** — at least one exactly-correct symbol in the top 5,
   no file-path fallback. This is the adoption signal.
2. tie → **held-out MRR (strict)**.
3. tie → **lowest cost**. A fixture whose cheap default already maxes held-out reports the
   *cheapest* config that reaches the ceiling — not a heavier config that merely ties.
   Cost order (cheap→expensive): `L1 < E0 < O0 < O0H < O0R < O0HR < O2 < O2H < R0 < O2HR < R1 < R2`.

Held-out splits are now **n=17–20 per fixture** (gin/rust/cjson/laravel 17–18; the rest
19–20). At n≈19 the 95% Wilson CI half-width is ≈ ±0.16, so a 0.05 held-s@5 gap is within
noise while a ≥0.15 gap is real. The winner is chosen on held-out because optimizing the
tuning split alone is overfitting; the tuning split (n=22–24) is shown alongside and used
by the honesty guards.

### Two honesty guards

The pure "highest held s@5" rule is overridden in two cases, both visible in the matrix:

1. **Rerank/HyDE tax on the tuning set.** A rerank/HyDE/heavy config that improves
   held-out but **regresses the larger tuning set** is not crowned (it is reported as the
   "pure held-out optimum" with a note). This rejected `express-js → O0R` (held r1 +0.05
   bought a tuning-r1 regression) and `spring → R2` (held s@5 0.89 bought a tuning-s@5
   regression 1.00→0.96).
2. **Spread overlap → cost.** A nondeterministic config (HyDE/rerank) whose rank-1
   advantage rests on a 3× spread that overlaps a cheaper config's is treated as tied, so
   cost breaks it toward the cheaper config.

### Determinism and the 3× rule

HyDE and the LLM reranker run at generation temperature > 0, so they are **nondeterministic**.
Therefore:

- **Deterministic configs** (`L1`, `E0`, `O0`, `O2`, `R1`) are measured once.
- **Nondeterministic configs** (any with HyDE or rerank: `O0H`, `O0R`, `O0HR`, `O2H`, `R0`,
  `O2HR`, `R2`) are scored **3×** via `bench/repeat-score.mjs`; the reported metric is the
  **median** and rank-1 carries its **min–max spread**. A nondeterministic config is
  winner-eligible only if reproduced 3×.

## Measurement protocol & environment

- **Cold, isolated builds.** `bench/cell.mjs` wipes `.graph-indexer/` before each build.
  Query-time configs (`*H`, `*R`, `*HR`, `R0`, `R2`) are scored on the already-built index
  of their base embed config (`--reuse`), so the expensive embed build runs once per
  (fixture, embed-model).
- **Ollama models present**: `nomic-embed-text`, `qwen3-embedding:4b`, `qwen2.5-coder:7b`
  (rerank), `qwen2.5-coder:1.5b` (enrichment + HyDE).
- **Coverage this pass.** The cheap + nomic-HyDE/rerank family (`L1, E0, O0, O0H, O0R, O0HR`)
  was measured for **all 18 fixtures** — the nomic family reuses the O0 build, so this whole
  phase has **zero qwen3 builds** and re-establishes the cheap-tier + HyDE/rerank winners at
  full power everywhere. The qwen3:4b family (`O2, O2H, R0, O2HR`) was measured for the **9
  contested/heavy fixtures** (nestjs, rust, spring, laravel, alamofire, gin, django, rails,
  symfony); enrichment (`R1, R2`) for the **4 fixtures** where it is a documented
  winner/contender (rust, spring, laravel, symfony). The remaining 9 fixtures get the cheap +
  nomic family only — qwen is pruned there with a per-fixture justification (cheap already
  wins and qwen3:4b is a documented negative for those language families; see "did NOT
  reproduce"). **152 cells total, all validated.**
- **Re-evaluated pruning.** The n=3 pass pruned 12 fixtures because their cheap config
  "saturated at held s@5 = 1.00." At n≈19 that saturation collapsed (only css remains at
  1.00), so the prune basis is gone — every fixture's heavy decision is now made on its
  measured high-power held s@5, not on a small-sample 1.00. Where qwen was still pruned it is
  because the cheap/nomic tier already wins by a margin and qwen is a documented regressor for
  that family, not because of a 1.00 ceiling.
- **Build cost is the binding constraint.** `qwen3-embedding:4b` indexes at ~0.7–3 chunks/s;
  a single qwen build ranges ~9 min (small fixtures) to ~70 min (rails, 7071 chunks), and
  enrichment builds are ~1.3× that. The grid survived **four power interruptions** mid-run;
  `bench/_rerun-v2.sh` is resumable at segment granularity (`.seg2__<fixture>__<seg>`
  markers), so each resume only redid the interrupted segment.
- **express-ts: NOT MEASURED.** Its upstream fixture repo (`microsoft/TypeScript-Node-Starter`)
  returns HTTP 404 and it has 0 held-out queries — unchanged from the prior pass.

## Reproduce

```bash
# one cell, cold build + strict score:
node bench/cell.mjs <fixture> <configId>            # e.g. rust R2
# a nondeterministic query-time config, 3× on the on-disk index of its base build:
node bench/cell.mjs rust O2                          # build qwen3 index
node bench/repeat-score.mjs rust R2 3               # score qwen3 + enrich + rerank 3×
# the full v2 grid (resumable at segment granularity, survives interruptions):
bash bench/_rerun-v2.sh phase1     # cheap + nomic family, all 18
bash bench/_rerun-v2.sh phase2     # qwen3 family, 9 contested/heavy
bash bench/_rerun-v2.sh phase3     # enrichment, 4 fixtures
# validate every query's ground truth resolves in the index (the gate):
node bench/verify-ground-truth.mjs
# regenerate the matrix + winners + confidence from bench/results/*.json:
node bench/synth-best.mjs --json --md
node bench/_confidence.mjs --md
```

### What this means for adoption

- **Maxed by the zero-dependency lexical default (L1 — no Ollama, no embeddings):**
  express-js, spring. **2 fixtures** (was 6 at n=3 — see "did not survive").
- **Best with a cheap embedding channel, no LLM stack:** axios, gin, android, aspnet,
  symfony, nvm (in-process **E0** — no Ollama daemon) and css (**O0** nomic, sharpens rank-1).
  **7 fixtures.** → Combined, **8 fixtures need nothing beyond the in-process default**
  (lexical + MiniLM, no external daemon).
- **Best with nomic embeddings + LLM rerank/HyDE (Ollama, but no qwen3 embedder):** nestjs,
  fastapi, react, django, rails, laravel, cjson, alamofire (**O0R** or **O0HR**, using
  `qwen2.5-coder:7b` as reranker). **8 fixtures** — a tier that did not exist at n=3, because
  rerank's rank-1/MRR sharpening on NL queries only became statistically visible with 17–20
  held-out queries.
- **Genuinely need the full heavy qwen3:4b + enrichment + rerank stack:** **rust** only
  (R2, held s@5 0.39→0.61). **1 fixture** (was 5 at n=3).

### Conclusions that did NOT survive the larger sample

These are the highest-value findings of this pass — n=3 claims that the higher-powered set
refuted:

1. **The "saturation" that justified pruning 12 fixtures was a small-sample artifact.** At
   n=3, twelve fixtures hit held s@5 = 1.00; at n≈19 only **css** does. Every "lexical
   saturates, embeddings add nothing" verdict (axios, fastapi, android, nvm, symfony) was the
   three easy held-out queries all hitting.
2. **symfony's "intent→identifier ceiling of 0.75 that no channel closes" was false.** Held
   s@5 is **0.95** at n=20 (every config); the 0.75 was 3 of 4 queries. symfony is a normal
   cheap-embed fixture, not a residual-gap fixture.
3. **spring does NOT need the heavy stack.** n=3 crowned `R0` (qwen3+rerank) at 0.67→1.00. At
   n=19 cheap and heavy tie at held s@5 0.84; the pure optimum `R2` reaches 0.89 but regresses
   the tuning set and is rejected. The zero-dependency lexical default is the recommended
   winner.
4. **Rerank does NOT regress rails — it HELPS it.** n=3 reported rerank dropping rails held
   s@5 0.67→0.33. At n=20, nomic+HyDE+rerank **lifts** it 0.40→0.50 (rank-1 0.25→0.45). The
   n=3 "regression" was one query.
5. **cjson's "rank-1 is 0.00 for every config" was false.** n=3 saw the right file but never
   the right symbol at rank-1. At n=18, **O0R reaches rank-1 0.72** — the within-file gap is
   largely a rerank-addressable ranking problem, not a hard ceiling.
6. **The heavy-qwen tier shrank 5→1 and a nomic-rerank tier of 8 emerged.** With enough NL
   held-out queries, the LLM reranker's rank-1/MRR sharpening is a real, repeatable signal on
   8 fixtures — but it runs on the *cheap* nomic index with `qwen2.5-coder:7b`; the expensive
   qwen3:4b **embedder** is needed only by rust.

### Configs whose advertised benefit did NOT reproduce (these conclusions held)

- **qwen3-embedding:4b (O2) is never a sole winner — confirmed at high power.** It ties nomic
  at best and **regresses held success@5 on gin (0.94→0.88) and django (0.95→0.89)**. The only
  place a qwen3 build earns its keep is rust's R2 (and there the lift is from
  enrichment+rerank, not the embedder alone).
- **Enrichment helps only rust, and actively hurts laravel.** On laravel, R1 holds held s@5
  but **drops the tuning split 0.82→0.55** (R2 0.64) — the known core-chunk coverage
  miscalibration (PageRank-by-file budget spent on Http controllers, starving Services/).
  Flagged, not fixed.
- **Rerank is double-edged on the tuning set, even where it helps held-out.** It is the right
  call on 8 fixtures' held-out, but it taxes the tuning symbolic set on JS (express-js) and
  spring — which is exactly why the honesty guards exist.

### The residual ceiling — hard queries no config solves

Stated honestly at the higher n:

- **rails** — held success@5 capped at **0.50**; the lowest ceiling of any fixture. The
  ~7k-chunk Ruby index has a deep semantic gap that even nomic+HyDE+rerank only halves.
- **rust** — best held success@5 **0.61** (R2); the only fixture still needing the full heavy
  stack, and even then 39% of held-out NL queries miss.
- **nestjs** — held success@5 ceiling **0.75**; the 0.70 cheap baseline is hard to beat.
- **fastapi/alamofire** — ceiling **0.80**; rerank gets them there from 0.70–0.75.
- **css remains the lone saturator** (held s@5 1.00), but even there held rank-1 tops out at
  0.85 — the right rule is found but not always ranked first.
