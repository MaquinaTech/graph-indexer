## 1. Output-rewriting layers for coding agents (RTK and similar)

### Takeaway
- **Mechanisms in use:** (1) *command rewrite* in a PreToolUse-style hook (`git status` → `rtk git status`; RTK, squeez, Devin/Codex/Copilot hooks); (2) *output replacement* in PostToolUse (`updatedToolOutput` in Claude Code, `modifiedResult` in Copilot CLI, `tool.execute.after` in OpenCode/Kilo; squeez, tokenslim, trace-mcp "mirrors", ggshield redaction); (3) *routing/deny* (context-mode denies Bash/WebFetch and points to its sandbox MCP tools; Serena denies repeated greps); (4) *API-boundary proxies* (headroom, pxpipe, llmtrim) that rewrite the whole request.
- **Reported savings are byte ratios of the filtered output, not bill reductions.** RTK's own docs now say so ("up to 90% of the bash output … not the same as cutting your bill by 90%", tokens = bytes/4).
- **Every independent end-to-end measurement of an output compressor found ≈0 or negative cost effect**: JetBrains (RTK +7.6% cost at low effort, p=0.004; ±0% high effort), Quesma (RTK +1% / +17% mean cost, −1/−2 pts pass rate, +18% turns on DeepSeek), PointFive paper (RTK −2.9% n.s.; a 38%-more-aggressive RTK-ML +6.8%; headroom proxy +46.4%), RTK's own paired benchmark (+0.2% cost, 5 new errors). Mechanism: bash output is a small share of billed input (cache reads dominate), and lossy output triggers extra turns that re-send the whole history.
- **The one positive end-to-end result for an output rewriter is narrow**: trace-mcp's Claude Code `updatedToolOutput` "mirror" cut cost 83% on a single synthetic task of 8 large Reads (vendor, n=5 runs); a 108-run internal three-arm run (−14% cost on 2–4-turn tasks) is cited but unpublished. A *skeleton* rewrite of Read failed its recall gate outright (34.8% evidence recall).
- **Known failure modes are concrete**: pipes (`rtk find | xargs wc` failed 10/10), silent corruption (tee'd filtered log → agent reported "0 clippy warnings"), lossy `cat` rewrite (+50% output tokens, +18% cost; RTK reverted `rtk read` to no filtering in v0.34.0), agent sees its original command but a different output format, hidden truncation, host classifier confusion (Codex), escape hatches that are themselves rewritten.
- **What did save money** in controlled A/Bs were *behaviour* changes injected as instructions (JetBrains benjamin-plus: −17.9% median cost, Read calls 144→57, quality tied) and graph tools gated to intervene only when the agent is crawling (trace-mcp detector: 0.88× cost).

## 2. Claude Code 2.1.280: exact contracts for rewriting reads and searches

### Takeaway
- `PostToolUse.hookSpecificOutput.updatedToolOutput` works for built-in tools **only if the value matches the tool's output schema exactly**; otherwise it is silently ignored. Shapes that have been used successfully in the wild: Read `{type:"text", file:{filePath, content, numLines, startLine, totalLines}}` and Bash `{stdout, stderr, interrupted, isImage}` (+ optional fields). MCP output is passed through unvalidated.
- The Read tool result the model sees is **line-number-prefixed text rendered from `content` starting at `startLine`**; a replacement that drops lines therefore renumbers them wrongly unless it is a single contiguous window [I]. Unchanged re-reads are deduplicated into a `file_unchanged` stub.
- `PreToolUse.updatedInput` replaces the whole input (Bash `command`, Read `offset`/`limit`); combine with `permissionDecision:"allow"` or `"ask"`. There are open reports of it being ignored for Bash (2.1.215 desktop) and of `updatedToolOutput` being ignored for Bash (2.1.163/2.1.177); a vendor measured both Read and Bash replacements reaching the model on 2.1.239. **Integrations must self-test on the installed version.**
- On deny, `permissionDecisionReason` (or exit-2 stderr) is returned to Claude as the blocked tool's error; the system prompt tells Claude to treat hook feedback "as coming from the user".
- Edit accepts a file read with explicit `offset`/`limit`; only an auto-truncated read carrying the `PARTIAL view` notice does not count. Newer models (after Opus 4.6/Haiku 4.5) may Edit files they never read, and single-file `cat/head/tail/sed -n/grep/rg` via Bash also satisfies read-before-edit.
- Grep/Glob are still absent by default on macOS/Linux/WSL; searches are Bash calls to embedded ugrep/bfs.
- Claude Code already manages old tool output itself (per-message caps, time-based microcompact clearing older tool results, auto-compact) and persists large Bash outputs (>~30,000 chars) to files, which shrinks the band where a rewriter can add value.
- An undocumented, EARLY ACCESS in-process plugin API ("function hooks", `mods/`, types written by 2.1.277) exposes `tool.call` middleware (deny, replace result, add context), `tool.describe` (rewrite built-in tool descriptions, un-defer MCP tools) and `prompt.context`.

### Cited Findings

**`updatedToolOutput` contract [V]** — [Hooks reference](https://code.claude.com/docs/en/hooks) (PostToolUse decision control)
- "`updatedToolOutput` | Replaces the tool's output with the provided value before it is sent to Claude. The value must match the tool's output shape." "For built-in tools, a value that doesn't match the tool's output schema is ignored and the original output is used. MCP tool output is passed through without schema validation. Stripping error details that Claude needs can cause it to proceed on a false assumption."
- "`updatedToolOutput` only changes what Claude sees. The tool has already run … Telemetry … captures the original output."
- `decision:"block"` + `reason` "adds the `reason` next to the tool result. Claude still sees the original output".
- Since v2.1.121 for all tools ("previously MCP-only") — [CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md).

**Built-in tool output shapes (what a replacement must match) [V]** — [Agent SDK TypeScript reference, Tool Output Types](https://code.claude.com/docs/en/agent-sdk/typescript)
- Bash: `{stdout, stderr, interrupted, isImage?, rawOutputPath?, backgroundTaskId?, noOutputExpected?, persistedOutputPath?, persistedOutputSize?, returnCodeInterpretation?, …}`; `stdout` = "The command's stdout and stderr, merged into one interleaved stream"; `stderr` = "Notices the tool itself adds".
- Read: union discriminated by `type`: `{type:"text", file:{filePath, content, numLines, startLine, totalLines, truncatedByTokenCap?}}` | `image` | `notebook` | `pdf` | `parts` | **`{type:"file_unchanged", file:{filePath}, source?:"seeded"}`** ("Set when the dedup matched a startup-seeded entry (CLAUDE.md / nested memory)").
- Grep: `{mode?, numFiles, filenames, content?, numLines?, numMatches?, totalFiles?, totalLines?, appliedLimit?, appliedOffset?}`. Glob: `{durationMs, numFiles, filenames, truncated, totalMatches?, countIsComplete?}`.
- PostToolUse receives the *structured* object; PostToolBatch receives "the serialized `tool_result` content the model sees … For `Read`, that means line-number-prefixed text rather than raw file contents" — [Hooks reference](https://code.claude.com/docs/en/hooks) (PostToolBatch input).

**Examples in the wild and whether replacement works**
- trace-mcp mirror (Claude Code 2.1.239, 2026-09-03) [V] — [e1-read-bash-mirror.md](https://github.com/nikolai-vysotskyi/trace-mcp/blob/main/benchmarks/e1-read-bash-mirror.md): harness message on mismatch "PostToolUse hook returned updatedToolOutput that does not match `<tool>`'s output shape; using original output". Captured envelopes: Read `{ "type": "text", "file": { "filePath", "content", "numLines": 5, "startLine": 1, "totalLines": 1003 } }`; Bash `{ "stdout", "stderr": "", "interrupted": false, "isImage": false, "noOutputExpected": false }`. Live: Read 30,140 → 2,459 chars (−91%) "reached the model"; Bash 3,952 → 1,212 (−69%) reached; Bash 30,000 chars did **not** (already persisted by the harness). "Noise filtering never runs on a `Read`" (package-manager patterns delete code).
- ggshield (GitGuardian, secret redaction) [V2, 3rd-party code] — [rust/hook/src/output.rs](https://github.com/GitGuardian/ggshield/blob/main/rust/hook/src/output.rs): replaces only Bash and Read ("only the shapes captured from a real payload count … Claude Code silently ignores a value that does not and shows the original"); Read replacement `{type:"text", file:{filePath: tool_input.file_path, content, numLines, startLine:1, totalLines}}`.
- squeez (Read/Grep/Glob/Monitor via `updatedToolOutput`, "Claude Code v2.1.119+") and tokenslim (Bash `{stdout, stderr, interrupted, isImage}`; Grep `content`; Glob `filenames`) [V, their repos].
- Bug reports [V2]: [anthropics/claude-code#68951](https://github.com/anthropics/claude-code/issues/68951) (June 2026) "PostToolUse `updatedToolOutput` silently ignored for built-in Bash tool (2.1.163/2.1.177) — regression; prior reports #65403/#67442/#54196 closed as duplicate, never fixed"; no CHANGELOG entry mentions a fix [V: CHANGELOG grep].
- Cache effect [V, vendor] — [mirror-prompt-cache.md](https://github.com/nikolai-vysotskyi/trace-mcp/blob/main/benchmarks/mirror-prompt-cache.md): because the rewrite changes only the newest message, it cannot invalidate a cached prefix. Corpus of 2,746 sessions / 113,501 requests: prefix breaks 1.76% without vs 1 of 41 after a rewrite. Live A/B, one task (8 large Reads, 9 turns): bare $1.030/$1.027/$0.778 vs mirror $0.165/$0.192 → **cache_write −95%, cache_read −59%, cost −83%**; recalls of spilled output: 0 of 48 rewrites. The same file cites an unpublished internal "108-run three-arm measurement" (TRA-749) with −14% cost on 2–4-turn tasks and 90.4% compression; no task list, solve rates or CIs are public.

**Read rendering, limits and dedup [V]**
- Read description served to newer models: "Reads up to ${MAX_LINES_CONSTANT} lines by default" (template `tool-description-readfile-compact.md`, ccVersion 2.1.268, in [Piebald](https://github.com/Piebald-AI/claude-code-system-prompts)); the constant renders as "2000" in the Read tool of the Claude Code session used for this research.
- "When a whole-file read exceeds the token limit, Read returns the first page with a `PARTIAL view` notice … A read that passes an explicit `offset` or `limit` and still exceeds the token limit returns an error" — [Tools reference](https://code.claude.com/docs/en/tools-reference). PARTIAL view since 2.1.145.
- Token cap: `CLAUDE_CODE_FILE_READ_MAX_OUTPUT_TOKENS` "Override the default token limit for file reads" — [env vars](https://code.claude.com/docs/en/env-vars); default not stated in current docs. Historically 25,000 ([#4002](https://github.com/anthropics/claude-code/issues/4002)); [#45019](https://github.com/anthropics/claude-code/issues/45019) reports 10,000 for some models [V2].
- 2.1.86: "Read tool now uses compact line-number format and deduplicates unchanged re-reads"; 2.1.260 fixed stale read tracking causing "File unchanged since last read" stubs — [CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md). Reminder text: "… (see "Contents of `<path>`" above) and has not changed on disk. Use that content instead of re-reading." (`system-reminder-file-already-in-context.md`, ccVersion 2.1.199).
- [I] Consequences for rewriting Read: (a) the model-visible text is numbered from `startLine`, so folding non-contiguous regions into `content` yields wrong line numbers for later `offset` reads or edits; (b) after a replaced first read, an unchanged re-read of the same file may come back as the `file_unchanged` stub pointing at the *replaced* text; (c) squeez/tokenslim avoid or limit first-read rewrites for this class of reasons.

**PreToolUse `updatedInput` (Bash command rewrite; Read offset/limit) [V]** — [Hooks reference](https://code.claude.com/docs/en/hooks)
- "Modifies the tool's input parameters before execution. Replaces the entire input object … Claude Code evaluates permission rules and a Bash command's auto-background eligibility against the input your hook returns, not the input Claude sent. Combine with `"allow"` to auto-approve, or `"ask"` to show the modified input to the user." `permissionDecisionReason`: "For `"allow"` and `"ask"`, shown to the user but not Claude. For `"deny"`, shown to Claude."
- CHANGELOG: 2.0.10 PreToolUse can modify inputs; 2.1.0 `updatedInput` allowed with `ask`; 2.1.85 `updatedInput` satisfies AskUserQuestion; 2.1.271 fixed cloud-session `updatedInput … failed schema validation`.
- Open reports [V2]: [#79321](https://github.com/anthropics/claude-code/issues/79321) "PreToolUse hook `updatedInput` is silently ignored for the Bash tool" (Claude Code 2.1.215 desktop app); [#47853](https://github.com/anthropics/claude-code/issues/47853) ignored for Edit, "works for Read and Bash"; [#44412](https://github.com/anthropics/claude-code/issues/44412) ignored for Agent; [#15897](https://github.com/anthropics/claude-code/issues/15897) fails when several PreToolUse hooks run; [#30770](https://github.com/anthropics/claude-code/issues/30770) replaces rather than merges.
- In use for Read: squeez injects `limit`/`head_limit` into Read/Grep/Glob [V, repo].

**What the model sees on a deny [V]**
- "A hook that blocks by exiting 2 routes the same way as "deny": Claude sees the stderr message as the denial reason." — [Hooks reference](https://code.claude.com/docs/en/hooks).
- System prompt (2.1.173): "Treat feedback from hooks, including `<user-prompt-submit-hook>`, as coming from the user. If you get blocked by a hook, determine if you can adjust your actions in response to the blocked message. If not, ask the user to check their hooks configuration." Additional context is rendered as "`<hookName>` hook additional context: …"; blocking errors as "`<hookName>` hook blocking error from command: "…": …" — [Piebald prompts](https://github.com/Piebald-AI/claude-code-system-prompts/tree/main/system-prompts).
- Phrase `additionalContext` as facts, not imperatives (prompt-injection defences) — carried over from prior notes [V there].

**Edit after partial reads [V]** — [Tools reference](https://code.claude.com/docs/en/tools-reference) (Edit tool behavior)
- "Read-before-edit: Claude reads the file in the current conversation before editing it, and a read cut short with a `PARTIAL view` notice doesn't count. Claude Opus 4.6, Claude Haiku 4.5, and older models always require the read. Newer models can edit an unread file when reading it wouldn't need a permission prompt and the Read tool is available." (relaxed handling since 2.1.208).
- Match against current disk content: "A file that changed on disk after Claude last read it can still be edited when `old_string` matches the current content exactly and unambiguously".
- "Viewing a file with Bash also satisfies the read-before-edit requirement when the command is `cat`, `nl`, `bat`, `batcat`, `head`, `tail`, `sed -n 'X,Yp'`, `grep`, `egrep`, `fgrep`, or `rg` on a single file with no pipes or redirects." (head/tail since 2.1.144, grep since 2.1.160.) 2.1.212: "Fixed a spurious "File has not been read yet" error when editing a file that had been read with offset/limit before resuming a session" → offset/limit reads count.
- Write: "files Claude has read only partially with a `PARTIAL view` notice require the read on every model".
- [I] Rewriting `cat f` into a custom command (e.g. `graph-indexer show f`) removes the Bash read-before-edit credit for older models.

**Search tools, Bash output limits and harness-side persistence [V]** — [Tools reference](https://code.claude.com/docs/en/tools-reference)
- "On macOS, Linux, and WSL, Claude Code leaves Glob and Grep out of the default tool set … the searches reach your hooks and permission rules as `Bash` calls." (The 2.1.117 changelog carved out npm-installed builds; current docs do not mention npm.)
- Bash: valid results inline "up to roughly 30,000 characters by default; past that, the path of a file … plus a preview of up to the first 2,000 characters"; failures "Inline up to roughly 10,000 characters" (head+tail). `BASH_MAX_OUTPUT_LENGTH` ≤150,000; `bashOutputMaxChars` ≤128,000 (2.1.261). Exit 1 is benign for `grep`, `rg`, `find`, `diff`, `git grep`, ….
- trace-mcp: "the compressible mass is bimodal, and the harness already owns the fat end"; 4 of 5 real outputs were under the 2,000-char rewrite threshold [V, vendor].

**PostToolBatch, timeouts, latency [V]** — [Hooks reference](https://code.claude.com/docs/en/hooks)
- PostToolBatch: "Runs once after every tool call in a batch has resolved, before Claude Code sends the next request … no matcher"; `additionalContext` "injected once before the next model call"; `decision:"block"`/`continue:false` stops the loop.
- "All matching hooks run in parallel." Default `timeout`: 600 s for command/http/mcp_tool, 30 s prompt, 60 s agent; 30 s on UserPromptSubmit/PreModelSwitch/PostModelSwitch; SessionEnd budget 1.5 s. "A timed-out `command`, `http`, or `mcp_tool` hook doesn't block the tool call"; an Agent SDK callback that times out *does* block it. `async: true` and `asyncRewake` run hooks in the background.
- Practice [V, repos]: codebase-memory 300 ms deadline; GitNexus 10 s hook / 7 s CLI timeout; RTK "<10ms" per rewrite (spawns `jq` + `rtk`); trace-mcp tree-sitter parse ~2 ms warm, "~40 ms per call in a per-call hook process" incl. Node boot.

**Claude Code's own context management [V]**
- "It clears older tool outputs first, then summarizes the conversation if needed." — [How Claude Code works](https://code.claude.com/docs/en/how-claude-code-works). `/usage` distinguishes "expected rebuilds" after "compaction or by clearing old tool results" — [Costs](https://code.claude.com/docs/en/costs).
- Source analysis of v2.1.88 (VILA-Lab, 2026-09-15): five pre-model stages — Budget Reduction ("Per-message tool-result size caps") → Snip (`HISTORY_SNIP`) → **Microcompact ("Clear older tool results"; "Time threshold on eligible main-thread requests, or an optional cache-editing path")** → Context Collapse (`CONTEXT_COLLAPSE`, read-time projection) → Auto-Compact — [architecture.md](https://github.com/VILA-Lab/Dive-into-Claude-Code/blob/main/docs/architecture.md) [V for the analysis; the source it reads is unofficial].
- After compaction, up to five recently read/edited files are re-read; a file over 5,000 tokens comes back as a path reference ("Referenced file") — [Context window](https://code.claude.com/docs/en/context-window).

**Early-access in-process "function hooks" (mods) [V]** — [mods/README.md](https://github.com/anthropics/claude-code/blob/main/mods/README.md), [mods/types/claude-code.d.ts](https://github.com/anthropics/claude-code/blob/main/mods/types/claude-code.d.ts) ("Written by Claude Code 2.1.277 … EARLY ACCESS: this surface may change between releases without notice"), [sec-default/README.md](https://github.com/anthropics/claude-code/blob/main/mods/sec-default/README.md)
- A plugin's `hooks/hooks.json` may name `"modules": ["./register.ts"]`; the module exports `register(on, options)` and hooks engine events as `($, e, next)` functions; "Function hooks give every plugin a say on every event, in chain order, and the plugins a person installs sit in the user tier".
- `tool.call`: "`next(e)` runs the hooks beneath, then core (the permission prompt, the tool itself). Return `{ deny: reason }` to refuse or `{ result }` to answer yourself"; "Core validates a hook's answer against the tool's output schema … maps it for the model with the tool's own mapper"; `context` = "What the model reads after the tool's result and the user never sees" (one reminder, like PostToolUse).
- `tool.describe`: rewrite a tool's `description` and set `isDeferred` ("moves the tool behind ToolSearch (true) or into the prompt's list (false)"); `prompt.context` edits the instruction-file list (the built-in `agents-md` mod implements AGENTS.md loading this way; Explore/Plan keep only managed files). Not mentioned in the public docs as of 2026-09-23.

### Gaps
- Whether #68951/#79321 are fixed in 2.1.280 is not stated anywhere; the only positive live evidence is trace-mcp on 2.1.239 (Read, Bash).

## 3. Capability tables across agents (September 2026)

### Takeaway
- **Transparent command rewrite** is available almost everywhere that has hooks: Claude Code, Codex, Cursor (IDE + CLI), Gemini CLI, Copilot CLI and VS Code (Local and Copilot harnesses), Devin Desktop/Devin CLI (ex-Windsurf), Kilo Code (new platform) and OpenCode (plugins), Cline CLI/SDK, Junie CLI (early access).
- **Output replacement for built-in read/search tools** exists in Claude Code (`updatedToolOutput`, shape-validated), Copilot CLI (`modifiedResult`), Gemini CLI (`AfterTool` deny+reason or `tailToolCallRequest`), OpenCode/Kilo (`tool.execute.after`) and Cline CLI/SDK (`afterTool.result`). Cursor replaces MCP outputs only; Codex only by *blocking* the result (the model then sees the reason as a failed call).
- **Context next to a tool result**: Claude Code, Codex, Gemini, Copilot CLI (10 KB cap), VS Code Local, Devin (PostToolUse). Cursor's `postToolUse additional_context` has been reported as not reaching the model since March 2026; Cline's VS Code hooks inject `<hook_context>` after the tool results.
- **Big 2026 changes**: Windsurf became Devin Desktop (2026-06-02) and **Cascade was removed in 3.9.19 (2026-09-08)**; Devin Local uses Claude-style hooks in `.devin/hooks.v1.json` and reads `.claude/` hooks by default. Kilo Code's VS Code extension was **rebuilt on the Kilo CLI / OpenCode server (GA 2026-04-02)** and gained the OpenCode plugin API. Google moved consumer Gemini CLI users to closed-source **Antigravity CLI** (Gemini CLI stops serving Pro/Ultra/free users 2026-06-18; the repo remains active). Junie gained **CLI-only hooks (early access, no PostToolUse)**; Junie inside the IDE runs over ACP and fires no hooks.
- Cross-loading: Copilot CLI and Devin CLI read `.claude/settings.json` hooks; Cursor imports Claude Code hooks by default ("Third-Party Imports"). One Claude-format hook script will run under several hosts with different semantics → it must detect the host from the payload (RTK does).

### Cited Findings (per agent; only what is new vs the prior notes)

**Codex [V]** — [output_parser.rs](https://github.com/openai/codex/blob/main/codex-rs/hooks/src/engine/output_parser.rs), [post_tool_use.rs](https://github.com/openai/codex/blob/main/codex-rs/hooks/src/events/post_tool_use.rs), [hook_runtime.rs](https://github.com/openai/codex/blob/main/codex-rs/core/src/hook_runtime.rs), [tools/registry.rs](https://github.com/openai/codex/blob/main/codex-rs/core/src/tools/registry.rs), [output_spill.rs](https://github.com/openai/codex/blob/main/codex-rs/hooks/src/output_spill.rs), [hooks/schema/generated](https://github.com/openai/codex/tree/main/codex-rs/hooks/schema/generated)
- PreToolUse output schema: `permissionDecision` (allow/deny/ask), `permissionDecisionReason`, `updatedInput`, `additionalContext`; "PreToolUse hook returned updatedInput without permissionDecision:allow" is rejected. context-mode pins "codex-cli 0.141.0" as the first release honouring allow+`updatedInput` and `additionalContext` ([codex-caps.mjs](https://github.com/mksglu/context-mode/blob/main/hooks/core/codex-caps.mjs)).
- PostToolUse: "PostToolUse hook returned unsupported updatedMCPToolOutput" → hook run Failed and its `additionalContext` is dropped (test `unsupported_updated_mcp_tool_output_fails_open`). `decision:"block"`: "A PostToolUse block rejects the result, not the already-completed tool execution" → `FunctionCallError::RespondToModel(reason)`; `continue:false`+reason replaces the model-visible output with the feedback.
- `additionalContext` default budget `DEFAULT_HOOK_OUTPUT_TOKEN_LIMIT = 2_500` tokens; larger text written to `<tmp>/hook_outputs/<thread>/…txt` with a head/tail preview; per-hook `additionalContextLimit` allowed on PreToolUse, PostToolUse, SessionStart, UserPromptSubmit, SubagentStart. Default hook timeout 600 s.
- SessionStart hooks are skipped for sub-agent sessions (`SessionSource::SubAgent(_) => return false`); SubagentStart covers them.
- Built-in `explorer` role for `spawn_agent`: "Use `explorer` for specific codebase questions. Explorers are fast and authoritative … you should trust the explorer results without additional verification … spawn up multiple explorers in parallel" ([role.rs](https://github.com/openai/codex/blob/main/codex-rs/core/src/agent/role.rs)).

**Gemini CLI [V]** — [docs/hooks/reference.md](https://github.com/google-gemini/gemini-cli/blob/main/docs/hooks/reference.md)

## 4. Research 2025–2026 on context management and compression for coding agents

### Takeaway
- **History-level masking is the strongest, cheapest lever, and harnesses already ship it.** Replacing old observations with placeholders halved SWE-agent cost with no significant loss on 4/5 models (Complexity Trap); LLM summarization was not better. Claude Code (microcompact), OpenCode (prune), Gemini CLI (output masking, experimental) and Anthropic's API (tool-result clearing) all do this → graph-indexer should not duplicate it.
- **Observation-level pruning with task-aware selectors saves 23–40% tokens at parity** (SWE-Pruner, SWE-Pruner Pro, LaMR, CoACT, AgentDiet) — but these either change the tool interface (a `context_focus_question` argument) or run a trained model inside the loop; PointFive's billed study shows aggressive per-output pruning *raised* cost in a real harness.
- **Representation evidence is against skeletons as a substitute for code the agent needs.** At oracle localization, UML skeletons/signatures of non-edited code resolved no more issues than deleting them, and NL summaries answered 3/45 behavioural probes vs 30/45 for source (act-context); trace-mcp's skeleton gate kept only 34.8% of the lines agents later used. Skeletons work as *maps for localization* (Agentless, Aider repo map), not as replacements for bodies.
- **Viewer granularity matters**: SWE-agent's 100-line window beat both a 30-line window and whole files; summarized search beat iterative search (2024). Compressed context resolved as well as whole files with 3–3.7× fewer tokens when the right units were chosen (oracle).

### Cited Findings

**History masking vs summarization**
- The Complexity Trap (Lindenbauer et al., JetBrains Research; NeurIPS 2025 DL4Code; arXiv 2508.21433): SWE-agent, SWE-bench Verified (500), masking = keep the last M=10 observations ("N=1_M=10"), summary = OpenHands-style every N=21 turns [V: repo CSVs](https://github.com/JetBrains-Research/the-complexity-trap/tree/main/auxiliary-data):

  | model | raw solve / $ | masking solve / $ | LLM-summary solve / $ |
  |---|---|---|---|
  | Gemini 2.5 Flash | 32.8% / 0.415 | 35.6% / 0.177 | 36.0% / 0.242 |
  | Gemini 2.5 Flash (thinking) | 40.4% / 0.556 | 36.4% / 0.242 (−4.0 pts, p=0.04) | 31.4% / 0.252 (−9.0 pts) |
  | Qwen3-Coder 480B | 53.3% / 1.288 | 54.8% / 0.610 | 53.8% / 0.637 |
  | Qwen3-32B | 17.0% / 1.117 | 15.0% / 0.554 | 16.0% / 0.500 |
  | Qwen3-32B (thinking) | 23.0% / 0.513 | 24.6% / 0.462 | 24.8% / 0.510 |

  README: "Current efficiency-oriented agent context management methods consistently and significantly reduce cost by around 50% without significantly degrading downstream task performance"; combining both gives a further 7%/11% reduction; generalizes to OpenHands.
- OpenHands `LLMSummarizingCondenser` (blog 2025-04-09): up to 2× lower per-turn cost; on full SWE-bench Verified at 100 iterations it resolved 200 vs 203 and "cost $40 more to run due to lower prompt cache utilization" [V2] — [OpenHands blog](https://www.openhands.dev/blog/openhands-context-condensensation-for-more-efficient-ai-agents).
- Anthropic context editing (2025-09-29): 100-turn web-search eval, context editing let agents finish workflows "while reducing token consumption by 84%"; +29% (context editing) and +39% (with memory tool) on an internal agentic-search eval [V2] — [Anthropic](https://www.anthropic.com/news/context-management). API: `clear_tool_uses_20250919` trigger 100K, keep 3 (prior notes [V]).
- Claude Code microcompact (time-threshold clearing of older tool results; cache-aware) — §2 [V].
- Gemini CLI (experimental, off by default): `contextManagement.tools.outputMasking` (protect newest 50,000 tokens, mask when ≥30,000 prunable, never the latest turn) and `tools.distillation` (truncate to 10,000 tokens; LLM-summarize above 20,000) [V] — [configuration.md](https://github.com/google-gemini/gemini-cli/blob/main/docs/reference/configuration.md).
- OpenCode prune: keeps the newest 40,000 tokens of tool output, replaces older outputs with "[Old tool result content cleared]" when ≥20,000 tokens are prunable (`compaction.prune`) [V] — [compaction.ts](https://github.com/sst/opencode/blob/dev/packages/opencode/src/session/compaction.ts).
- Codex: `context_management` feature (UnderDevelopment, off) adds `new_context` ("Start a new context window. Does not clear, reset, or otherwise affect environment state") and `get_context_remaining` tools [V] — [features/src/lib.rs](https://github.com/openai/codex/blob/main/codex-rs/features/src/lib.rs), [new_context_window_spec.rs](https://github.com/openai/codex/blob/main/codex-rs/core/src/tools/handlers/new_context_window_spec.rs); shipped in CLI 0.153.0 (2026-09-03) [V2 via VILA-Lab notes].
- AgentDiet (arXiv 2509.23586, TOSEM/PACM SE): trajectory reduction with a reflection module; input tokens −39.9% to −59.7%, cost −21.1% to −35.9%, performance −1.0% to +2.0% (Claude 4 Sonnet, Gemini 2.5 Pro; SWE-bench Verified, Multi-SWE-bench Flash) [V2].
- ACON (arXiv 2510.00615; AppWorld, OfficeBench, multi-objective QA — not coding): peak tokens −26–54% with task success maintained/improved; distilled compressor keeps 95% of teacher accuracy [V2]; repo [V](https://github.com/microsoft/acon).
- "An Empirical Study of Harness Design for Coding Agents" (arXiv 2609.20804, Sep 2026; 4 models, SWE-bench Verified + Terminal-Bench 2.1, 176 settings, 5 context strategies): "context management extends execution trajectories without substantially altering agent behavior"; rules: "stage cheap elision before LLM summarization, drop the recall tool"; bash-capable models do well with a bare shell at lower cost [V2].
- TokenPilot (arXiv 2606.17016): filter noise at ingestion to keep the KV prefix stable, evict segments only after their lifecycle ends [V2 via VILA-Lab list].

**Observation-level pruning of tool outputs**
- SWE-Pruner (ByteDance et al., arXiv 2601.16746, Jan 2026): 0.6B "neural skimmer" selects lines given an agent-written goal; integration wraps `bash`/`cat` with an optional `context_focus_question` argument (Claude Agent SDK via MCP; OpenHands) [V: README](https://github.com/Ayanami1314/swe-pruner). "23–54% token reduction on … SWE-Bench Verified and up to 14.84× compression on … LongCodeQA with minimal performance impact"; with Claude Sonnet 4.5: prompt −38.7%, completion −40.8%, total −39.2%, rounds −18.3% [V2].
- SWE-Pruner Pro (arXiv 2607.18213, Jul 2026): a small head on the agent's own hidden states labels lines keep/prune; up to 39% prompt+completion tokens saved; +3.8% resolve on MiMo-V2-Flash [V2].
- LaMR (arXiv 2605.15315): with Sonnet 4.5 saves 30.5% tokens vs SWE-Pruner's 23.1%, +0.2 pt success [V2].
- CoACT (arXiv 2607.02911, 2026-07-03): compressor trained with a "next-action preservation" reward; −33.0% total tokens on SWE-bench Verified with three models, "close to the uncompressed agent" [V2].
- LongCodeZip (ASE 2025, arXiv 2510.00446): function-level conditional-perplexity ranking + block knapsack; up to 5.6× compression without degrading completion/summarization/QA (single-turn, not agentic) [V2]; repo [V](https://github.com/YerbaPage/LongCodeZip).
- OCD, oracle-guided code distillation (arXiv 2603.28119, 2026-03-30): resolves 93.8–99.2% of the union of cases solved by any baseline; "compression is more effective when it preserves repair-sufficient context, rather than maximizing token reduction or similarity" [V2].
- PointFive (arXiv 2607.12161): per-output compression in a real billed harness: see §1 (RTK-ML −38.4% text → +6.8% cost) [V2].

**Representations: skeletons, folded views, maps, windows**
- act-context, "What Context Does a Coding Agent Actually Need to Act?" (Sam-Bodden, arXiv 2607.09691, June 2026; Claude Sonnet 4.6 single-shot, oracle localization, all 70 multi-file SWE-bench Verified instances, pre-registered) [V: paper/main.tex](https://github.com/integrallis/act-context/blob/main/paper/main.tex):

  | arm | resolved | mean context tokens | tokens / resolve |
  |---|---|---|---|
  | whole gold files | 19/70 (27.1%) | 25,426 | 93,700 |
  | tiered (UML class skeleton, signature+doc for non-edited units) | 23/70 (32.9%) | 8,629 | 26,300 |
  | keep edited units / drop the rest | 25/70 (35.7%) | 6,876 | 19,300 |

  "Rendering the non-locus remainder as class skeletons and signatures carries no measurable resolve signal over just dropping it" (tier vs keep/drop McNemar p=0.754); NL summaries answer 3/45 behavioural probes vs 30/45 for source, "for frontier and 3B summarizers alike" (README); temperature-0 runs flip ~9% of per-instance outcomes.
- trace-mcp skeleton gate (TRA-861) [V, vendor] — [README](https://github.com/nikolai-vysotskyi/trace-mcp/blob/main/benchmarks/skeleton-gate/README.md): 493 real Read/Bash calls from 2,416 Claude Code transcripts; "evidence" = lines later quoted, used in an Edit `old_string`, or carried into a later call.
  - Read subset (180): signatures-only skeleton 34.8% recall at 71.6% cut; structural units 60.6% at 51.2%; a plain window at the same budget 63.9% at 50.7%; shipped 24/12-line window 36.7% at 86.1%.
  - Oracle ceilings: perfect structural selection cuts only **16.7%** at 100% recall; perfect line selection 92%. "Evidence touches 1.88 of 4.68 units per file, and those units hold 83% of the file's bytes." Verdict: "Compress tool output more cleverly than a deterministic window" is closed; HCP-style skeleton compression "does not transfer to a per-call output rewriter".
- SWE-agent ACI ablations (NeurIPS 2024, SWE-bench Lite, GPT-4 Turbo): file viewer 100 lines 18.0%, 30 lines 14.3%, full file 12.7%; summarized search 18.0% vs iterative 12.0%; no linting 15.0%; no edit tool 10.3% [V2] — [arXiv 2405.15793](https://arxiv.org/abs/2405.15793).
- Agentless (arXiv 2407.01489): localization over a "skeleton format" per file (class/function headers, class fields and method signatures, module/class comments) before reading full code; 32.00% on SWE-bench Lite at $0.70 [V2].
- Aider repo map: tree-sitter symbols ranked by a PageRank-style graph over references, fit to `--map-tokens` (default 1k) [V2] — [aider docs](https://aider.chat/docs/repomap.html).
- Moatless Tools: semantic search + viewing only relevant code spans; 39% solve at $0.14/issue with Claude 3.5 Sonnet, 30.7% at $0.01 with DeepSeek V3 (SWE-bench Lite) [V2].
- Kilo/OpenCode read tool guidance: "Avoid tiny repeated slices (30 line chunks). If you need more context, read a larger window." [V].

### Gaps
- None of the pruning papers measured billed cost under prompt caching in a production harness (PointFive is the exception and found the opposite sign for aggressive pruning).
- No study evaluates a *code-graph-aware* observation rewriter (e.g. folding bodies of functions the task graph deems irrelevant) end to end; act-context tested only static signature tiers and explicitly excluded interaction-level/call-edge artifacts.

## 5. Fast-context subagents (2026) and where agent tokens go

### Takeaway
- Fast-context/explore subagents are now standard (Claude Code Explore, Codex `explorer` role, Cursor Explore + Instant Grep, Devin/Windsurf Fast Context, Morph WarpGrep via MCP). The only public end-to-end numbers remain WarpGrep v2's (+2.1 to +3.7 pts SWE-bench Pro, −15.6% cost).
- **Read operations dominate transcript mass, but not the bill.** Reads are ~67–76% of tokens in mini-SWE-agent trajectories (SWE-Pruner) and native Read+Bash are 26% (human) / 57% (agent runs) of Claude Code transcript mass, yet in one heavy corpus they were only ~12% of billed input (system prompt + tool definitions 51.6%, cache reads ~93% of token classes). Turn count × per-turn floor explains cost (Harness Tax R²=0.99). → Cutting *turns* and *wrong reads* beats compressing individual outputs.

### Cited Findings

**Fast-context subagents**
- Claude Code Explore: 2.1.198 "now inherits the main session's model (capped at opus) instead of running on haiku" [V CHANGELOG]; a built-in agent listing (93 tokens, 2.1.173; matches Explore's read-only role) reads "Read-only search agent for broad fan-out searches — when answering means sweeping many files … It reads excerpts rather than whole files, so it locates code; it doesn't review or audit it" (2.1.173) [V, Piebald `agent-prompt-read-only-search-agent.md`]; Explore/Plan keep only managed instruction files (built-in `agents-md` mod) [V].

- Cursor: Explore subagent "in its own context window with a faster model"; Instant Grep = local trigram index, "16.8 seconds with ripgrep versus 13 milliseconds" locally (243 ms with a network hop); semantic search +12.5% QA accuracy (prior notes) [V2] — [Cursor blog](https://cursor.com/blog/fast-regex-search).

- Morph WarpGrep v2 (2026-03-02): +2.1 (Opus 4.6: 55.4→57.5%), +3.1 (Codex), +3.7 (MiniMax) on SWE-bench Pro; ~17% fewer input tokens, 13% fewer turns, 12% faster, **−15.6% cost**, −28% latency; up to 36 tool calls in <5 s; exposed as MCP to Claude Code, Codex, Cursor [V2] — [Morph](https://www.morphllm.com/blog/warpgrep-v2).

**Where the tokens go**
- SWE-Pruner trajectory analysis (mini-SWE-agent, SWE-bench Verified): Claude Sonnet 4.5 spends **76.1% of tokens on read-type operations**, execute 12.1%, edit 11.8%; GLM-4.6: read 67.5% (2.89M), edit 18.5%, execute 14.0% [V2].

- trace-mcp wallet share (2,907 sessions, 120,969 requests, $10,371 billed input; one heavy user, 2026-05-28…09-06) [V, vendor] — [wallet-share.md](https://github.com/nikolai-vysotskyi/trace-mcp/blob/main/benchmarks/wallet-share.md): system prompt + tool definitions 51.6% of billed input; injected tool/skill/agent listings 15.1%; tool-call arguments 7.2%; **Bash output 7.1%; Read output 5.0%**; hook output 2.6%; files + CLAUDE.md 2.6%; other MCP 1.7%; trace-mcp 1.6%; output tokens 9.0% of input+output; median first-request prompt 59,040 tokens; all tool output 15.4% → "Roughly 10–12%" is the ceiling of output compression. Token classes (other corpus): cache_read 92.6%, cache_write 2.8%, uncached 4.6%.
- PointFive: cache traffic ≈87% of reconstructed cost (§1) [V2]. "The cache share of an agentic bill" (Open-SWE-Traces replay): output 9–18%, cache 82–91% [V2 via awesome-ai-tokenomics].

## Implications for graph-indexer

**Which agents let a tool transparently…**

1. **Rewrite search/read shell commands** (PreToolUse-class, before execution): Claude Code (`updatedInput` + `permissionDecision`; self-test at install because of #79321/#3018), Codex (`updatedInput` only with `allow`, ≥0.141), Cursor IDE + cursor-agent (`updated_input`), Gemini CLI (`BeforeTool tool_input`), Copilot CLI (`modifiedArgs` / PascalCase `updatedInput`), VS Code Local (`updatedInput`, Local schema), Devin Desktop/CLI (`updatedInput`, merged), Kilo Code new platform and OpenCode (`tool.execute.before`), Cline CLI/SDK (`beforeTool.input`), Junie CLI (EA). Claude Code, Copilot CLI and OpenCode/Kilo can also rewrite *Read* arguments (e.g. add `offset`/`limit`).
2. **Replace read/search outputs**: Claude Code (`updatedToolOutput`, exact envelope; or the early-access `tool.call` function hook), Copilot CLI (`modifiedResult`), Gemini CLI (`AfterTool` deny+reason / `tailToolCallRequest` to route a grep into a graph query), OpenCode/Kilo (`tool.execute.after`), Cline CLI/SDK (`afterTool.result`). Cursor: MCP outputs only. Codex: only by blocking the result (reads as a failed call) — do not use.
3. **Only add context**: VS Code Local, Devin, Junie CLI (PreToolUse only), Cline VS Code/JetBrains (`contextModification`), Codex for outputs, Cursor in practice (post-tool context reported not delivered; pre-tool context undocumented).
4. **Only MCP + instructions/skills**: Junie in JetBrains IDEs (ACP, no hooks), Kilo legacy v5.x, Zed and Antigravity IDE (prior notes), Aider (no MCP), any host with hooks disabled. Put the pointer in AGENTS.md and server `instructions`; note Copilot CLI shows non-allowlisted servers' instructions only on demand and Cline's source shows no use of them.

**What the evidence says to expect**
- **Output compression of shell/read output: plan for ≈0 net cost effect and non-zero risk.** Independent A/Bs: RTK +7.6% (JetBrains, low effort), +1%/+17% (Quesma), −2.9% n.s. (PointFive); more aggressive pruning +6.8%, proxy +46.4%. The ceiling is small because tool output is ~15% of billed input and cache reads dominate; lossy output adds turns that re-send the whole history.
- **Changing how the agent looks things up pays**: injected lookup discipline −10…−18% median cost at equal quality (benjamin-plus); graph tools that stay silent until the agent is crawling −11–12% (trace-mcp detector), while eager interception costs 1.44–1.72× on "where is X" questions; RL search subagents −15.6% cost with +2–4 pts (WarpGrep); structural index −19% cost per solve (Code Isn't Memory). History masking (−50% cost) is already done by the harnesses.
- **Do not replace code the agent chose to read with skeletons/summaries**: skeleton recall 34.8% (trace-mcp), skeleton tiers ≈ deleting (act-context), NL summaries 3/45 vs 30/45 probes. Skeletons are useful *before* reading (localization maps), and compact targeted context can match whole files at 3–3.7× fewer tokens when the right units are selected.

**Design rules for graph-indexer hooks (derived; mark [I])**
1. Default mode = **context-only, fail-open, fast (≤300 ms)**: SessionStart/SubagentStart pointer (facts, ≤1–2 KB; inject rather than rely on a skill folder); PreToolUse on `Bash(grep|rg|ugrep|find)`/`Grep`/`Glob` adding symbol definitions with `path:start-end` line ranges; PreToolUse on `Read` without `offset`/`limit` of a large file adding a non-blocking outline ("`parseConfig` L41–88, `loadApp` L90–140…") so the next read is a keyhole read. Never deny by default; if nudging, gate on a crawl detector (≥3 navigation calls without progress).
2. **Output replacement only in opt-in, narrow cases**, each with an escape hatch exempt from rewriting: (a) huge grep outputs (group by symbol with counts, keep `path:line:content` lines so pipes still work); (b) re-reads already seen unchanged (Claude Code dedups natively — skip there). Never fold a first Read into non-contiguous pieces: the Read renderer numbers `content` from `startLine`, so folded views get wrong line numbers; put outlines in `additionalContext` instead. Preserve exact envelopes (Read `{type:"text", file:{filePath, content, numLines, startLine, totalLines}}`; Bash `{stdout, stderr, interrupted, isImage}`); make rewrites byte-deterministic (content-addressed spill names) for cache stability.
3. **Command rewriting** (e.g. `grep -rn Foo` → `graph-indexer grep Foo`) only when the agent is the terminal consumer: no `|`, `>`, `tee`, `$(…)`, heredoc; output must stay grep-compatible and disclose the transformation in one header line; skip on Codex (its safety classifier does not unwrap wrappers) and on older Claude models where a rewritten `cat` loses the Bash read-before-edit credit.
4. **One hook binary, host-detected**: Claude-format hook files are also executed by Copilot CLI, Cursor (Third-Party Imports) and Devin (`read_config_from.claude`); detect the host from payload keys (`tool_name`/`toolName`/`toolArgs`/`hook_event_name`/Cursor fields) and emit that host's fields (e.g. Cursor requires `{}` and fails closed on invalid JSON; Copilot CLI fails closed on crashes; Codex rejects `updatedInput` without `allow` and fails a hook that returns `updatedMCPToolOutput`).
5. **MCP tool results should carry verbatim code slices with real line numbers** sized to a symbol plus a margin (~50–100 lines, cf. SWE-agent's 100-line optimum and "keyhole reads"): newer Claude models may Edit without a prior Read, and Edit needs exact `old_string` text. Keep schemas free of `const`/`additionalProperties` for Gemini-family hosts (Antigravity CLI silently drops such tools).
6. **Watch Claude Code's early-access function hooks** (`tool.describe` can rewrite the built-in Bash/Read descriptions and un-defer graph-indexer tools; `tool.call` can annotate or replace results through the engine's own mapper), but do not ship on them until documented.
7. **Measure cost per solved task, not bytes**: paired runs, provider-billed cost with caching, turns, output tokens, cache reads, and pass rate; report medians and totals; expect effects within ±10–20% and ~9% per-instance noise at temperature 0; include a "where is X" slice, a crawl slice and an edit slice; check that the payload reached the model (adoption) in every treated run.
